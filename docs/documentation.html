Muallim ul-Qur'an PWA (v7.0.0)

Offline-first, student-only Progressive Web App for learning Qur'anic Arabic across 7 Units, 114 Lessons, 14,956 Items, 570 Lesson Quizzes, 4 Summative Model Papers, and a 6-Page Mushaf Coverage Showcase.

Live PWA (GitHub Pages): https://nomaanc.github.io/muallim/

GitHub Repository: github.com/nomaanc/muallim

Core Features (v7.0.0)

7-Unit Curriculum

114 lessons and 14,956 items in 4 languages (Hinglish, English, Nastaliq Urdu, Devanagari Hindi) with 100% NFC harakat parity.

114 Lazy Lesson Chunks

Per-lesson payloads under data/lessons/s{u}l{l}.json for instant navigation without loading full unit files.

Verse Clause Stepper

Slash-segmented verses render interactive clause-by-clause Arabic and meaning chips with Student Mode tap-to-peek.

Leitner 5-Box SRS

Flashcard drill with Mistakes deck, prompt direction modes, Qari playback, and browser TTS fallback.

570 Lesson Quizzes

5 randomized 4-language questions per lesson plus Units 5–7 Root-and-Affix Morphology Builder.

4 Model Papers

Official workbook exams (vol1, u4, u5, timed 120-min u7) with Bayyinat continuous passages.

6-Page Mushaf Showcase

Page 176 passages comparing learner progress against the post-Unit-7 comprehension benchmark.

9-Pillar Spiral & Roots

Trace 9 cross-cutting grammar pillars and browse cognate nouns and verbs by trilateral root.

Interactive Visuals

Per-unit SVG grammar diagrams, shuffled prediction prompts, collapsible Steps & Examples drawer, and lightbox.

Offline Audio & PWA

Qari MP3 range chaining cached in muallim-audio-v1 plus Service Worker muallim-v7.0.0-cache.

Architecture (v7.0.0)

Pure Vanilla ES Modules (Zero Runtime Build Step)

Muallim runs natively in modern browsers using ES modules, HTML5 native <dialog> modals, and CSS Custom Properties:

  • index.html: Student-only shell containing the exact 5 <dialog> modals (#lesson-picker-dialog, #search-dialog, #drill-dialog, #practice-dialog, #settings-dialog) and #lesson-content-mount.
  • css/styles.css & css/layout.css: OKLCH color tokens, 3 themes (parchment, night, sepia), RTL/LTR language typography, verse stepper, and exam/Mushaf views.
  • js/core/*: 9 focused modules (store, router, renderer, audio, srs, quiz, exams, search, sync) coordinated by js/app.js.
  • js/visuals/*: Lazy-loaded unit SVG modules (unit1.js–unit7.js) managed by loader.js and visual-helper.js.
Zero runtime bundlers or transpilers. package.json devDependencies are used strictly for automated node --test unit tests and Playwright E2E checks.

Developer Guide

Local Development

  1. Clone the repository: git clone https://github.com/nomaanc/muallim.git
  2. Start a static server from the repo root: python -m http.server 8080
  3. Open http://127.0.0.1:8080/.

Critical Invariants

Student-Only Surface: Zero admin.html, teacher.html, ustaad, or broadcast UI, routes, or Firestore collections.
Terminology & Harakat: Keep "Exercise" (never "Mashq"); display "Unit" in UI labels; preserve 100% NFC Arabic diacritics and immutable item IDs across all 14,956 items.
Windows PowerShell: Chain commands with ; (never &&) and set $env:PYTHONIOENCODING='utf-8' before running Python scripts.
Deploy Exclusions: images/, docs/, skills/, tests/, and scripts/ are excluded from GitHub Pages and Firebase Hosting deployments.

Firebase Student Sync (/user_data/{userId})

Cloud sync is lazy-loaded only when a learner explicitly signs in (Email/Password or Google Sign-In) or resumes an opted-in session. All legacy collections (/users, /pushed_exams, /exam_results, /muallim_students, /muallim_broadcasts) are removed and denied by default.

  • Owner-Only Rules: isOwner(userId) enforces request.auth != null && request.auth.uid == userId on read, create, update, and delete.
  • Immutability & Role Lock: uid and createdAt cannot change after creation; role is restricted to 'student' or 'guest'.
  • Tombstone Reconciliation: Bounded deletedItems (max 5,000 entries) and fieldUpdatedAt (max 50 entries) maps ensure unstarred items, cleared notes, and uncompleted lessons stay deleted across devices.
  • Emulator Tests: Run Jest rule tests against the Firestore emulator in security_rules_test_firestore/.

Verification & CI

GitHub Actions (.github/workflows/ci-deploy.yml) gates every push to main with:

# 1. Python curriculum & asset budget gate
PYTHONIOENCODING=utf-8 python scripts/verify_v6.py

# 2. Node built-in unit tests
npm run test:unit

# 3. Playwright headless Chromium E2E suite
npx playwright test

After verification passes, CI publishes static runtime assets (including data/lessons/ and data/exams/ while excluding images/, docs/, skills/, tests/, and scripts/) to GitHub Pages and Firebase Hosting + Firestore Rules.
