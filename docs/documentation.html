📖 Muallim ul-Qur'an PWA

A standalone Progressive Web App for learning Qur'anic Arabic vocabulary via Hinglish (Hindi in Roman script). 7 Units, multiple lessons per unit, offline-capable.

Live URL: https://nomaanc.github.io/muallim/

Admin Dashboard: https://nomaanc.github.io/muallim/admin

Repository: github.com/nomaanc/muallim

Features

📚

7-Unit Book

Full Arabic vocabulary textbook with Hinglish translations across 7 units.

✏️

Custom Answers

Edit any translation with your own Hinglish answer, saved locally.

⭐

Starred Items

Star vocabulary words for drill and review.

🔀

Vocabulary Drill

Flashcard drill from starred items or selected lessons.

🔍

Full-Text Search

Search across all Arabic and Hinglish text in the book.

🎓

Exam Engine

Self-practice exam with configurable scope and PDF export.

🔖

Bookmarks

Bookmark any card. Resume from exact position with highlight animation.

🌙

Parchment, Night, and system themes. Teacher/Student display modes.

🔊

Text-to-speech for Arabic words via Web Speech API.

📱

PWA / Offline

Installable as a PWA. Service Worker caches content for offline use.

Optional login with email/password. Role-based access (student/admin).

Architecture

Single-File PWA

The entire application lives in a single HTML file: pwa/index.html (~4.2 MB, ~77k lines). This includes all CSS, JavaScript, and inline book data (window.PWA_BOOK_DATA).

⚠️ No build tools. There is zero npm, no Vite, no Webpack. Edit the HTML file directly. No compilation step.

Developer Guide

Setup

  1. Clone the repository: git clone https://github.com/nomaanc/muallim.git
  2. Working directory: e:\AIPROJECTS\PROJECTS\translate-hinglish-skill\pwa\
  3. Open index.html in a browser — no local server needed for basic testing
  4. For Firebase features: need to be online (or use emulators)
ℹ️ The .git folder lives inside pwa/, not the project root. Run all git commands from within the pwa/ directory.

Edit Workflow

# 1. Edit pwa/index.html
# 2. Sync to mirror file:
Copy-Item index.html final-book-7units.html -Force

# 3. Commit and push:
git add -A
git commit -m "feat(pwa): description of change"
git push origin main

# GitHub Pages deploys automatically in ~30 seconds

PowerShell Rules

  • Use ; not && to chain commands in PowerShell
  • Set $env:PYTHONIOENCODING='utf-8' before running Python scripts
  • Use Select-String to search within index.html (not grep)

Searching index.html

# Find a function or pattern:
Select-String -Path "index.html" -Pattern "functionName" | Select-Object -First 10

# Count lines:
(Get-Content "index.html").Count

# Find and check the App exports:
Select-String -Path "index.html" -Pattern "Object.assign\(App" | Select-Object -First 5

JavaScript Syntax Validation

$env:PYTHONIOENCODING='utf-8'
python -c "
import re
content = open('index.html', encoding='utf-8').read()
scripts = re.findall(r'<script(?:\s[^>]*)?>(.+?)</script>', content, re.DOTALL)
for i, s in enumerate(scripts):
    with open(f'_tmp_s{i}.js', 'w', encoding='utf-8') as f: f.write(s)
print(f'Extracted {len(scripts)} blocks')
"
node --check _tmp_s0.js  # Check each extracted block

Critical Invariants

🚫 NEVER translate "Exercise" to "Mashq" — it stays as "Exercise" in all Hinglish text.
🚫 NEVER strip or alter Arabic harakat (diacritics). Preserve them exactly as-is.
⚠️ Always show "Unit" not "Stage" in UI labels (internal data uses stage_id).
ℹ️ All Hinglish follows SOV syntax (Subject-Object-Verb), not English SVO.

Data Schema

PWA_BOOK_DATA (inline JSON)

window.PWA_BOOK_DATA = {
  stages: {
    "Stage1": {              // Key: "Stage1" through "Stage7"
      "S1L1": {              // Key: S{stage}L{lesson}
        title: "Lesson Title",
        sections: [
          {
            type: "two_col_text",
            items: [ { arabic: "...", hinglish: "..." }, ... ]
          },
          {
            type: "two_col_numbered_list",
            items: [ { id: 1, arabic: "...", hinglish: "..." }, ... ]
          },
          // ... other section types
        ]
      }
    }
  }
};

Known Firebase Scope Bug (FIXED — commit 8b0a871)

initFirebaseOnLoad() was defined inside the App IIFE but called from outside the IIFE in the DOMContentLoaded listener. The function was invisible to code outside the IIFE.

Fix: Added initFirebaseOnLoad to Object.assign(App, {...}) to export it. DOMContentLoaded now calls App.initFirebaseOnLoad() instead of bare initFirebaseOnLoad().
