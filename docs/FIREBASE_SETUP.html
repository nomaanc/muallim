What You Get with Firebase

⭐

Starred Words Sync

All students' starred vocabulary saved to cloud. Admin sees every student's starred Arabic words.

✏️

Custom Answers Sync

Students' personal translations synced. Teacher sees each custom answer for every vocab item, per student.

🎓

Exam Scores Sync

Every attempt (score, grade, breakdown, timestamp) stored per student. Admin sees full history.

📢

Broadcast Alerts

Teacher types a message in Admin Panel → all students with app open see it as an instant toast alert.

📲

Cross-Device

Student uses phone and tablet — data auto-merges. Works offline, syncs when back online.

€FREE

Free Forever

Firebase Spark plan: 1 GiB storage, 50K reads/day, 20K writes/day — enough for a full class.

ℹ️
The app works fully offline without Firebase. All reading, bookmarks, vocab drill, and exams continue to work with no internet. Firebase only adds cloud sync on top.

Create a Firebase Project

~5 min · Free
1

Go to console.firebase.google.com and sign in with your Google account.

2

Click "Add project". Enter a name like muallim-quran. Click Continue.

3

On the Google Analytics screen, disable analytics (not needed). Click Create project.

4

Once created, click Continue. You’ll land on the Project Overview page.

5

Click the Web icon (</>) to add a web app. Enter a nickname like Muallim Web. Do NOT check “Firebase Hosting”. Click Register app.

6

Firebase shows you a config object. Copy the { … } object:

// Example — your real values will differ:
{
  "apiKey": "AIzaSyXXXXXXXXXXXXXXXX",
  "authDomain": "muallim-quran.firebaseapp.com",
  "projectId": "muallim-quran",
  "storageBucket": "muallim-quran.appspot.com",
  "messagingSenderId": "123456789012",
  "appId": "1:123456789012:web:abcdef1234"
}
⚠️
Is the API key safe? Yes — for a web PWA protected by Firestore Security Rules, the API key alone cannot read or write data. The rules (Step 4) enforce all access control. Never share your Firebase service account private key (that is a different file, only used server-side).

Enable Firestore Database

~3 min
1

In the Firebase Console left sidebar → Firestore Database (under Build).

2

Click “Create database”.

3

Choose “Start in production mode”. Click Next.

4

Select a Cloud Firestore location — choose the region nearest to your students. For Pakistan: asia-south1 (Mumbai). Click Enable.

💡
The location cannot be changed later. asia-south1 (Mumbai) gives the best latency for Pakistan and India.
4

Set Firestore Security Rules

~5 min · Critical
🚨
This step is required. Without proper rules, anyone who finds your API key could read or modify all student data. The rules below protect everything correctly.
1

In the Firestore Console, click the “Rules” tab at the top.

2

Delete all existing rules and paste the rules from Section 14 below.

3

Click “Publish”. Rules take effect within ~1 minute.

ℹ️
Why no login? The app works as an offline PWA and requiring students to create Google accounts adds friction. Instead, each device gets a stable UUID — the security rule verifies a device can only write its own document. This is appropriate for a classroom Qur'an study app where authentication overhead outweighs the benefit.

Connect the App — Paste Your Config

~2 min · Teacher device only
1

Open the Muallim app at nomaanc.github.io/muallim/.

2

Tap the ☰ menu button (top right corner).

3

Scroll to the bottom of the menu. Enter the Teacher PIN (default: 786) and tap “Unlock Admin Panel”.

4

In the Admin Panel, tap “⚙ Configure Firebase”.

5

Paste your Firebase config JSON into the text area. Only paste the { … } object, not the surrounding JavaScript code.

⚠️
If Firebase Console showed: const firebaseConfig = { … }; — only paste the part inside = { … };, i.e. just the curly braces and their contents.
6

Tap “💾 Save & Connect”. The badge turns green: “☁ Firebase connected”.

7

The app immediately syncs your local data (starred, custom answers, exam history) to Firestore. Future changes sync within ~1.5 seconds (debounced).

Embed Config for All Students (Recommended)

~3 min · One-time
💡
The teacher paste (Step 5) connects your device. To make ALL student devices auto-connect without any setup, embed the config directly into the HTML file and push to GitHub.

Open pwa/final-book-7units.html in a text editor. Find this block near the top of the file:

<!-- Firebase SDK (modular, loaded async only when config is set) -->
<script type="module" id="firebase-module-loader">
  // Firebase is loaded dynamically via App.initFirebase() after user provides config
</script>

Replace it with:

<!-- Firebase auto-config: embedded so all devices auto-connect -->
<script>
  try {
    if (!localStorage.getItem('muallim_firebase_config')) {
      localStorage.setItem('muallim_firebase_config', JSON.stringify({
        apiKey: "YOUR_API_KEY",
        authDomain: "YOUR_PROJECT.firebaseapp.com",
        projectId: "YOUR_PROJECT_ID",
        storageBucket: "YOUR_PROJECT.appspot.com",
        messagingSenderId: "YOUR_SENDER_ID",
        appId: "YOUR_APP_ID"
      }));
    }
  } catch(e) {}
</script>

Replace the placeholder values with your real Firebase config values, then commit and push to GitHub. Every student who opens the app will automatically connect to Firestore.

Firestore Data Structure Explained

The app uses a flat, efficient structure — one Firestore document per student device:

Firestore Root
│
├── muallim_students/             ← collection
│   │
│   └── dev_550e8400-e29b.../      ← document per device (UUID key)
│       │
│       ├── deviceId           → "dev_550e8400..."   stable browser UUID
│       ├── name               → "Ali Hassan"        student's entered name
│       ├── lastSeen           → Timestamp           server time of last sync
│       ├── currentStage       → number              last lesson position (1-7)
│       ├── currentLesson      → number              last lesson position (1-N)
│       │
│       ├── starred            → Array of objects
│       │     Each item: { key, arabic, hinglish, stage, lesson }
│       │     Max ~500 items (well under Firestore limits)
│       │
│       ├── customAnswers      → Map / object
│       │     Key: vocab item identifier e.g. "S1L3_s2_4"
│       │     Value: student's custom translation string
│       │
│       ├── examHistory        → Array of objects (last 50 attempts)
│       │     Each: { id, studentName, stage, lesson, date,
│       │             score, grade, correct, total, breakdown }
│       │
│       └── bestScore          → number              highest exam % ever
│
└── muallim_broadcasts/           ← collection
    │
    └── bc_1724887200000/         ← document per broadcast (timestamp key)
        ├── message            → "Exam tomorrow at 3pm"
        ├── sentAt             → Timestamp
        └── sentBy             → "Teacher"

Design Decisions

DecisionReason
One document per deviceAtomic writes, no subcollections → fewer Firestore reads (critical for free tier).
UUID device ID, no authNo login friction for students. The security rule prevents cross-device writes without blocking reads.
starred as ArrayEntire star list written in one atomic operation. Simple to display in admin. Max ~500 stars per student is realistic.
customAnswers as MapDirect O(1) key→value lookup. Merges cleanly with setDoc(merge:true).
Last 50 exams onlyKeeps document size small (Firestore limit: 1 MiB per document). Students rarely need exams older than 50 attempts.
Server timestamp for lastSeenUses Firebase server time, not device clock — accurate sorting even if a device has wrong clock.
1.5s debounceRapid starring of 10 words = 1 write, not 10. Protects daily quota dramatically.

Firebase Console doesn't have built-in CSV export. Use Firestore Console → three-dot menu → Export collection (exports as NDJSON). Or use the free tool firestore-export.web.app to export as CSV.

Students who have the app open see a green toast notification at the bottom of the screen within a few seconds. New broadcasts from the last 5 minutes are shown on load.

Enable Background Push Notifications (FCM) Optional

~10 min
ℹ️
The Broadcast feature (Step 10) works without FCM — it shows in-app toasts when the student has the app open. FCM adds background push (notification shown even when the app is closed, like a WhatsApp message).

11.1 — Generate VAPID Key

1

Firebase Console → Project Settings (gear icon) → Cloud Messaging tab.

2

Under Web Push certificates, click “Generate key pair”. Copy the VAPID Key (a long base64 string).

11.2 — Create the Service Worker File

Create pwa/firebase-messaging-sw.js:

// firebase-messaging-sw.js — place in pwa/ folder
importScripts('https://www.gstatic.com/firebasejs/10.12.0/firebase-app-compat.js');
importScripts('https://www.gstatic.com/firebasejs/10.12.0/firebase-messaging-compat.js');

firebase.initializeApp({
  apiKey: "YOUR_API_KEY",
  authDomain: "YOUR_PROJECT.firebaseapp.com",
  projectId: "YOUR_PROJECT_ID",
  storageBucket: "YOUR_PROJECT.appspot.com",
  messagingSenderId: "YOUR_SENDER_ID",
  appId: "YOUR_APP_ID"
});

const messaging = firebase.messaging();

messaging.onBackgroundMessage(function(payload) {
  self.registration.showNotification(
    payload.notification?.title || 'Muallim ul-Qur\'an',
    {
      body: payload.notification?.body || payload.data?.message || '',
      icon: '/muallim/icons/icon-192.png',
      badge: '/muallim/icons/icon-192.png',
      tag: 'muallim-broadcast'
    }
  );
});

11.3 — Embed FCM Token Registration in the App

In final-book-7units.html, find the App.enablePushNotifications function. After Notification.requestPermission() returns 'granted', add:

const { getMessaging, getToken, onMessage } = await import(
  'https://www.gstatic.com/firebasejs/10.12.0/firebase-messaging.js'
);
const messaging = getMessaging(_fbApp);
const swReg = await navigator.serviceWorker.register('/muallim/firebase-messaging-sw.js');
const token = await getToken(messaging, {
  vapidKey: 'YOUR_VAPID_KEY_HERE',    // from Step 11.1
  serviceWorkerRegistration: swReg
});
if (token && _db && window._FS) {
  const { doc, updateDoc } = window._FS;
  await updateDoc(doc(_db, studentDocPath()), { fcmToken: token });
  showToast('✅ Push notifications enabled!');
}

// Also listen for foreground messages
onMessage(messaging, (payload) => {
  showToast('📢 ' + (payload.notification?.body || ''), 6000);
});
💡
For most classroom use, the in-app Broadcast (Firestore-based) is sufficient. Only add FCM if you specifically need to reach students when their app is closed.

Free Tier Limits & Quota Safety

ResourceFree LimitEstimated Usage (30 students)Status
Firestore Reads50,000/day~60 (2 per student load)✓ Safe
Firestore Writes20,000/day~60–300 (debounced)✓ Safe
Storage1 GiB total~0.15 MB (5 KB × 30 students)✓ Safe
Network egress10 GiB/monthMinimal (JSON only)✓ Safe
💡
Debouncing is critical: The app waits 1.5 seconds after the last change before syncing, so rapidly starring 10 words = 1 write, not 10.

Scaling up: If your class grows beyond ~500 students, consider Firebase Blaze (pay-as-you-go). 1 million reads costs about $0.06 — negligible at classroom scale.

Monitor: Firebase Console → Usage and billing tab → Firestore section. Set a budget alert at $1 to get an email if usage unexpectedly spikes.

Full Firestore Rules (Copy-Paste Ready)

💡
These rules are production-ready. Copy them exactly — replace all existing content in the Rules editor, then Publish.
rules_version = '2';

service cloud.firestore {
  match /databases/{database}/documents {

    // ─── STUDENT DOCUMENTS ──────────────────────────────────
    // One doc per device (UUID key). Device can write its own
    // doc only. All docs readable (teacher admin reads all).
    match /muallim_students/{deviceId} {

      allow write: if
        request.resource.data.deviceId == deviceId
        && request.resource.data.keys().hasAll(['deviceId', 'name'])
        && request.resource.data.deviceId is string
        && request.resource.data.name is string
        && request.resource.data.name.size() <= 100;

      allow read: if true;
    }

    // ─── BROADCAST MESSAGES ──────────────────────────────────
    // Readable by all (students receive broadcasts).
    // Write requires valid string message <= 500 chars.
    // Update/delete not allowed (broadcasts are immutable).
    match /muallim_broadcasts/{broadcastId} {
      allow read: if true;
      allow create: if
        request.resource.data.message is string
        && request.resource.data.message.size() > 0
        && request.resource.data.message.size() <= 500
        && request.resource.data.keys().hasAll(['message', 'sentAt']);
      allow update, delete: if false;
    }

    // ─── DEFAULT: DENY ALL OTHER PATHS ───────────────────────
    match /{document=**} {
      allow read, write: if false;
    }
  }
}
